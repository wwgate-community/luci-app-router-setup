# luci-app-router-setup

Мастер первоначальной настройки роутера для OpenWrt: интернет (WAN), локальная
сеть (LAN) и Wi-Fi — на одной странице LuCI, в четыре вкладки.

Внутреннее имя компонентов — `routersetup` (конфиг, init-скрипт, страницы).

## Возможности

- **WAN**: DHCP, статический IP, PPPoE, L2TP, PPTP, а также «интернет по Wi-Fi
  от другого роутера» (WISP) — с выбором сети из результатов сканирования.
- **Клонирование MAC** WAN-порта, если провайдер привязывает подключение к нему.
- **Свои DNS-серверы** для WAN (или получение от провайдера).
- **LAN**: адрес роутера; маска приводится к CIDR-виду (netifd считает адрес без
  маски за `/32`, и DHCP на lan молча ломается).
- **Wi-Fi**: общий SSID для обоих диапазонов или раздельные 2.4/5 ГГц. Пароль
  обязателен — открытая сеть не разворачивается.
- **IPv6**: выключение/включение.
- Пункт меню можно скрыть (`hide_menu`), тогда мастер остаётся доступен в
  «Система → Быстрая настройка» и оттуда же возвращается в главное меню.

## Как это работает

Приложение хранит свои значения в отдельном конфиге `/etc/config/routersetup` и
не редактирует `network`/`wireless` напрямую из браузера:

1. **Зеркалирование (при загрузке).** `/etc/init.d/routersetup` читает живое
   состояние системы и переносит его в `routersetup`, чтобы мастер всегда
   открывался с текущими значениями.
2. **Применение (после сохранения).** Сохранение в UI пишет только
   `routersetup`; по триггеру procd init-скрипт разворачивает эти значения в
   `network`, `wireless` и `dhcp`, после чего перезагружает сеть с задержкой,
   чтобы браузер успел получить ответ.
3. **Защита от повторного применения.** Настройки разворачиваются, только если
   конфиг записан меньше минуты назад и ещё не применялся для этой ревизии
   (`recently_saved`). Обычный `reload` сервиса ничего не переписывает.

Такое разделение даёт предсказуемый откат: `routersetup` — это намерение
пользователя, а `network`/`wireless` — результат, который init-скрипт собирает
заново при каждом применении.

## Установка

Готовые пакеты — во вкладке [Releases](../../releases): `.ipk` для 24.10 и
`.apk` для snapshot. Пакет архитектурно-независим (`LUCI_PKGARCH:=all`) и
ставится на любое железо.

```sh
# 24.10 и старше
opkg install luci-app-router-setup_*.ipk
# snapshot
apk add --allow-untrusted luci-app-router-setup-*.apk
```

## Сборка из исходников

Пакет собирается штатным OpenWrt SDK как обычный luci-app:

```sh
# в дереве SDK/buildroot
cp -r luci-app-router-setup package/
make package/luci-app-router-setup/compile V=s
```

В репозитории есть workflow `.github/workflows/build.yml`: он собирает `.ipk` и
`.apk` и прикрепляет их к релизу по тегу `v*`, либо запускается вручную со
вкладки **Actions**.

## Локализация

Русский **входит в основной пакет**, отдельный `luci-i18n-*` не нужен: исходный
каталог лежит в `po-ru/router-setup.po`, а скомпилированный `.lmo` закоммичен в
`root/usr/share/router-setup/i18n/` и оттуда копируется в i18n-каталог LuCI при
установке.

После правки `po-ru/router-setup.po` каталог нужно пересобрать:

```sh
po2lmo po-ru/router-setup.po \
  luci-app-router-setup/root/usr/share/router-setup/i18n/router-setup.ru.lmo
```

Язык интерфейса: `uci set luci.main.lang=ru`.
